# AI Exception Explainer

Understand exceptions instantly using AI.

An AI-powered application that lets developers and QA engineers paste Java exceptions, Spring Boot stack traces, Selenium errors, Playwright errors, API errors, SQL errors, and generic logs — and receive a structured, human-friendly analysis generated by a local LLM (Ollama) or Groq.

## ✨ Features

- **Paste anything**: exceptions, stack traces, logs, error messages, SQL errors, API errors
- **Auto-detection**: the backend classifies the input type (Exception / Log / API Error / SQL / Playwright / Selenium) — no tabs or manual selection
- **File & PDF upload**: drag-and-drop text logs, stack traces, SQL files, or PDFs
- **Structured AI analysis** covering:
  - Exception type
  - Root cause (human-friendly)
  - Technical explanation
  - Suggested fix (with code examples)
  - Best practices
  - Prevention tips
  - Confidence level (High / Medium / Low)
- **Two LLM providers**: local **Ollama** (auto-detected installed models) and **Groq** (server-side API key)
- **Preferences/Settings**: choose provider + default model outside the main form
- **Multi-model comparison**: run the same input across up to 4 real, installed models
- **Live model discovery**: the model list comes from the actual Ollama installation — never hardcoded
- **Modern dark UI** — rounded cards, gradient buttons, smooth animations, fully responsive
- **Robust error handling** — provider offline, missing API key, timeouts, invalid responses, unsupported uploads, backend unavailable

## 🚀 Getting Started

### Prerequisites

- **Java 21** (JDK)
- **Maven 3.9+**
- **Node.js 18+** (npm)
- **Ollama** installed and running — see [ollama.com](https://ollama.com)
- (Optional) **Groq API key** — set `GROQ_API_KEY` for cloud analysis

### 1. Pull a model into Ollama

```bash
ollama pull qwen3:8b
```

Any model you pull locally will appear in the Settings model list automatically.

### 2. Start the backend

```bash
cd backend
mvn clean install
mvn spring-boot:run
```

The backend runs on **http://localhost:8080**.

### 3. Start the frontend

```bash
cd frontend
npm install
npm run dev
```

The frontend runs on **http://localhost:5173** and proxies `/api` calls to the backend.

### 4. Use it

1. Open **Settings** (gear icon) and pick a provider + default model
2. Paste an exception / stack trace / log / SQL / API error, or drop a file
3. Click **Analyze**
4. Read the structured AI explanation

## ⚙️ Configuration

All backend configuration lives in [`backend/src/main/resources/application.properties`](backend/src/main/resources/application.properties):

| Property                    | Default               | Description                          |
| --------------------------- | --------------------- | ------------------------------------ |
| `ai.default-provider`       | `ollama`              | Default provider when a request omits it |
| `ollama.base-url`           | `http://localhost:11434` | Ollama server URL               |
| `ollama.model`              | *(empty)*             | Optional fallback; models are discovered live |
| `ollama.timeout-ms`         | `120000`              | Max wait for Ollama                  |
| `ollama.max-tokens`         | `2048`                | Max generated tokens                 |
| `ollama.temperature`        | `0.2`                 | Sampling temperature                 |
| `groq.base-url`             | `https://api.groq.com/openai/v1` | Groq API base URL         |
| `groq.api-key`              | `${GROQ_API_KEY:}`    | Server-side API key (env)            |
| `groq.model`                | `${GROQ_MODEL:}`      | Server-configured Groq model         |
| `app.max-compare-models`    | `4`                   | Max models in a comparison           |
| `app.allowed-file-extensions` | `.txt,.log,...`     | Upload allowlist                     |
| `spring.servlet.multipart.max-file-size` | `5MB`    | Max upload size              |
| `app.cors.allowed-origins`  | `http://localhost:5173` | Allowed frontend origins        |
| `server.port`               | `8080`                | Backend port                         |

**Groq:** set the key via environment variable (never in the repo):

```bash
export GROQ_API_KEY=your_key_here
export GROQ_MODEL=llama-3.3-70b-versatile
```

## 🧠 How It Works

1. The frontend POSTs `{ exception, provider, model }` to `/api/analyze`.
2. The backend **auto-detects** the input type (exception, log, SQL, API error, Playwright/Selenium).
3. A persona-specific prompt instructs the LLM to act as an expert and **respond with JSON only**.
4. The prompt is sent to the selected provider (Ollama `/api/generate` or Groq `/chat/completions`).
5. The response is parsed (code fences stripped, JSON extracted, validated) into a structured `Analysis`.
6. The result is returned as a typed DTO and rendered in the AI Response Card.

## 🛡️ Error Handling

The app handles all major failure modes with friendly messages:

- Ollama unavailable / model not pulled
- Groq API key missing / API failure
- Selected Ollama model no longer installed
- Timeout
- Invalid / non-JSON AI response
- Empty input
- Unsupported file type / oversized upload / file extraction failure
- Backend unavailable
